# Microsoft 365 anbinden

Die **echte** Lage eures Tenants auf die Wand — nicht der öffentliche
Änderungs-Feed, sondern das Service Health Dashboard.

> **Warum überhaupt eine App-Registrierung?** Einen öffentlichen
> Service-Health-Feed gibt es nicht mehr. Was Microsoft öffentlich anbietet,
> meldet *Änderungen und Releases*, keine Störungen. Was **euren** Tenant
> trifft, steht ausschließlich im Service Health Dashboard — erreichbar nur
> über die Graph-API, und die verlangt eine registrierte Anwendung.

---

## Das Sicherheitsversprechen

| | |
|---|---|
| **Berechtigungen** | genau **eine**: `ServiceHealth.Read.All` (Anwendung) |
| **Was damit möglich ist** | Dienstzustände und laufende Vorfälle **lesen** |
| **Was damit nicht möglich ist** | Postfächer, Dateien, Benutzer, Teams-Inhalte, Änderungen jeder Art |
| **Wo das Secret liegt** | `config/secrets.env` (chmod 600), nie im Browser |
| **Wer es sieht** | nur der Container `m365` — er läuft unprivilegiert und schreibgeschützt |

Die ausgelieferte Datei `/data/m365.json` enthält **nur Zustände** — kein
Token, kein Secret, keine Benutzerdaten.

---

## Schritt 1 — App registrieren

Im **Microsoft Entra Admin Center** (`entra.microsoft.com`):

1. *Identität → Anwendungen → App-Registrierungen → Neue Registrierung*
2. **Name:** `NOC-Wand Service Health` (ein sprechender Name hilft beim
   späteren Audit)
3. **Kontotypen:** *Nur Konten in diesem Organisationsverzeichnis*
4. **Umleitungs-URI:** **leer lassen** — dieser Dienst meldet sich mit
   Client-Credentials an und braucht keinen Rückkanal
5. *Registrieren*

Notiere von der Übersichtsseite:
- **Anwendungs-ID (Client)** → `M365_CLIENT_ID`
- **Verzeichnis-ID (Mandant)** → `M365_TENANT_ID`

## Schritt 2 — Die eine Berechtigung

1. *API-Berechtigungen → Berechtigung hinzufügen → Microsoft Graph*
2. **Anwendungsberechtigungen** wählen (**nicht** „Delegiert" — es meldet sich
   kein Mensch an)
3. `ServiceHealth.Read.All` suchen und auswählen
4. **Administratorzustimmung erteilen** — ohne diesen Klick liefert die API
   `Authorization_RequestDenied`

> Steht in der Liste noch `User.Read` von der Registrierung: **entfernen.**
> Was nicht gebraucht wird, gehört nicht in die Anwendung.

## Schritt 3 — Secret erzeugen

1. *Zertifikate & Geheimnisse → Neuer geheimer Clientschlüssel*
2. **Gültigkeit:** so kurz wie eure Prozesse erlauben — 12 Monate ist ein
   guter Kompromiss, 24 das Maximum
3. Den **Wert** sofort kopieren (er wird nie wieder angezeigt) →
   `M365_CLIENT_SECRET`
4. **Ablaufdatum in euren Kalender eintragen.** Läuft das Secret ab, meldet der
   Dienst `AADSTS7000215` und die Karte bleibt leer.

## Schritt 4 — Eintragen und prüfen

```bash
cd ~/dashy
nano config/secrets.env
```

```
M365_TENANT_ID=00000000-0000-0000-0000-000000000000
M365_CLIENT_ID=11111111-1111-1111-1111-111111111111
M365_CLIENT_SECRET=...
```

```bash
chmod 600 config/secrets.env
./scripts/update.sh
docker compose exec m365 python /app/health.py --test
```

`--test` meldet sich an, liest einmal die Dienstliste und **schreibt nichts**.
Erwartete Ausgabe:

```
Anmeldung erfolgreich, Token 3599s gueltig.
Berechtigung ok: 34 Dienste lesbar.
```

Dann der erste echte Durchlauf:

```bash
docker compose exec m365 python /app/health.py --once
```

## Wenn es klemmt

Der Dienst übersetzt die kryptischen Microsoft-Codes:

| Meldung | Bedeutung | Lösung |
|---|---|---|
| `AADSTS7000215` | Client-Secret falsch oder abgelaufen | neues Secret erzeugen |
| `AADSTS700016` | Anwendungs-ID im Tenant unbekannt | Client-ID prüfen |
| `AADSTS90002` | Tenant-ID unbekannt | Verzeichnis-ID prüfen |
| `Authorization_RequestDenied` | Berechtigung fehlt **oder** Administratorzustimmung nicht erteilt | Schritt 2 Punkt 4 |
| `CERTIFICATE_VERIFY_FAILED` | SSL-Inspection im Weg | Firmen-CA — siehe README |

---

## Was danach passiert

Der Dienst fragt alle 5 Minuten ab und schreibt `state/m365.json`:

- **Dienstzustände** — jeder Dienst auf `ok` / `warn` / `crit` abgebildet
- **Laufende Vorfälle** — nur unerledigte, höchstens zwölf

Eine Entscheidung darin ist wichtig: **Ein laufender Vorfall wiegt schwerer als
die Übersichtsangabe.** Microsoft meldet in `healthOverviews` gern noch
`serviceOperational`, während für denselben Dienst ein Incident offen ist. Die
Wand zeigt in dem Fall den *schlechteren* Wert — sonst stünde dort „alles gut",
während die Anwender schon anrufen.

Nur bestimmte Dienste anzeigen (in `.env`):

```
M365_SERVICES=Exchange Online,Microsoft Teams,SharePoint Online
```

---

## Wenn das Secret kompromittiert wurde

1. Entra → *Zertifikate & Geheimnisse* → betroffenes Secret **löschen**
2. Neues erzeugen, in `config/secrets.env` eintragen
3. `./scripts/update.sh`
4. *Überwachung → Anmeldeprotokolle*, gefiltert auf die Anwendung: prüfen, ob
   sie von einer fremden Adresse benutzt wurde
